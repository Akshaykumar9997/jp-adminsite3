The Leads and Customer Support pages are read-only. They use the signed-in administrator's session and the existing public publishable key; no admin-site server secret is needed. Existing lead policies and Flutter files are unchanged. Refresh reads the latest database values.

Customer Support submits from the client site's server to the new crm.customer_support table using its existing SUPABASE_SECRET_KEY. The migration is supabase/migrations/20261008065515_customer_support.sql and has been applied to project xssjgzzhcudktrkruitb. It stores name, phone, city, email, project/invoice reference, topic, preferred contact, message, consent, ID and creation time. RLS allows active administrators to SELECT; anonymous reads and authenticated inserts, updates and deletes are denied. Service-role inserts and reads are allowed. No notification or support-status workflow is added.

Export Excel downloads genuine .xlsx files containing every record matching the current filters, including records beyond the displayed page. Dates use the browser's local timezone, with the To date inclusive. Leads use Flutter's Pending, Measurement, Approved, Rejected and Converted order; legacy statuses remain visible and export under OTHER. The first seven columns follow Flutter's export, with ID, referral fields, coordinates and user ID appended. Support exports all table fields. Customer text is written as strings, never formulas.

Records load in batches of 500 and display 50 per page. The export uses the currently loaded data; refresh before exporting if the app has just changed a lead. ExcelJS is loaded only when exporting. Its uuid dependency is pinned to a patched version, and source-map-js was updated within its existing dependency range. npm audit reports zero vulnerabilities.
